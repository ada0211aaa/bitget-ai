## 2. 背景

当前页面已经能展示回测结果、新闻事件和交易解释，但信息仍然偏散。多只股票同时出现时，用户和评委不容易快速看懂“这一笔买入或卖出到底为什么发生”。

从美股消息面交易产品专家视角看，比赛第一版不应该追求股票数量多，而应该让一支股票的解释链足够清楚。评委更关心系统是否能把真实事件、技术信号、交易动作和回测结果串起来，而不是页面里堆很多卡片。

因此本轮将展示范围收敛为 `NVDAUSDT / 英伟达`，用类似 Excel 的交易决策明细表作为核心页面，让每一笔买入、卖出、观望原因都能被直接阅读和复核。

## 3. 目标

1. 页面默认只围绕 `NVDAUSDT / 英伟达` 展示，不再把多只股票混在一个主视图里。
2. 把买入、卖出的原因做成类 Excel 明细表，重点解释“什么时间、因为什么事件、什么指标、所以做了什么动作”。
3. 每一笔交易都展示中文解释，避免用户只能看到英文枚举值或技术字段。
4. 保持比赛安全边界：只做回测和模拟展示，不下单、不查账户、不展示密钥。
5. 为后续调整买卖指标打基础：先看清楚现有触发原因，再决定策略指标是否需要重做。

## 4. 非目标

1. 本轮不做真实交易、自动下单、账户读取或持仓读取。
2. 本轮不做多股票对比大盘，不展示完整股票池排行榜。
3. 本轮不重写一套复杂交易策略，不做参数自动寻优。
4. 本轮不新增自定义新闻爬虫，优先继续使用现有事件文件和 Bitget 官方技能口径。
5. 本轮不把页面改造成大型前端项目，不引入 React、Vite、数据库或后台任务。

## 5. 使用场景

| 场景 | 使用者 | 触发条件 | 预期结果 |
| --- | --- | --- | --- |
| 比赛评委查看 Demo | Bitget Hackathon 评委 | 打开本地 Web 页面 | 第一屏能看到这是 NVDA 单股票回测解释台，并能进入交易明细表 |
| 用户复盘买卖原因 | 用户 | 看到某一笔买入或卖出 | 能在同一行看到新闻事件、技术指标、综合判断和中文解释 |
| 用户判断指标是否合理 | 用户、开发者 | 发现交易结果不理想 | 能通过明细表定位是新闻信号、技术信号还是规则触发口径不清 |
| 后续实现指标优化 | 开发者 | 用户确认下一轮要调整策略 | 以明细表中暴露的问题为依据，而不是盲目修改买卖规则 |

## 6. 功能范围

### 6.1 必须实现

1. 默认展示标的固定为 `NVDAUSDT / 英伟达`。
2. 页面主区域新增或改造为“交易决策明细表”。
3. 明细表至少包含以下列：
   - 序号
   - 交易时间
   - 标的
   - 动作：买入 / 卖出 / 观望
   - 成交价或触发价
   - 交易数量或仓位变化
   - 匹配新闻 / 事件标题
   - 新闻来源
   - 新闻发布时间
   - 新闻情绪：利好 / 利空 / 中性
   - 技术原因
   - 综合观点
   - 为什么买 / 为什么卖
   - 回测后续结果
4. 如果一笔交易没有匹配到新闻事件，表格必须明确显示“未匹配到 24 小时内新闻事件，主要由技术信号触发”，不能留空。
5. 页面保留深色中文风格，但信息密度要更像投研表格，减少大段分散卡片。
6. 页面顶部保留安全提示：只读回测，不下单、不查账户、不展示密钥。
7. 数据来源继续使用现有回测产物和事件产物，不新增实盘接口。
8. 对现有买卖指标只做“展示和解释”，不在本轮直接重写策略指标。

### 6.2 可以后置

1. CSV / Excel 导出按钮。
2. 多股票切换器。
3. 更复杂的新闻情绪评分模型。
4. 可点击展开每条新闻原文链接。
5. 独立的指标调参页面。
6. Playbook 官方回测结果的更深度结构化展示。

### 6.3 明确禁止

1. 禁止实现真实下单、自动交易、账户读取、余额读取、持仓读取。
2. 禁止在代码、日志、文档、页面中写入密钥、token、私钥或真实账户信息。
3. 禁止启动后台交易任务、监控任务、守护进程或定时任务。
4. 禁止为了页面展示而伪造“真实已成交订单”。
5. 禁止把新闻/事件展示成投资建议，必须保持“回测解释信号”口径。

- 不允许执行真实资金相关动作。

## 10. 风险与回退

| 风险 | 影响 | 预防方式 | 回退方式 |
| --- | --- | --- | --- |
| 单股票后样本变少 | 页面看起来交易次数少 | 明确这是第一版解释型 Demo，不追求覆盖所有股票 | 恢复多股票展示或后续增加股票切换 |
| 明细表字段过多 | 页面拥挤 | 保留核心字段，低优先级信息后置到展开详情 | 先隐藏低优先级列 |
| 现有解释数据不足 | “为什么买/卖”仍然不够清楚 | 基于现有事件、技术原因生成中文解释 | 后续补充解释生成逻辑 |
| 用户发现指标确实不合理 | 需要调整策略 | 本轮只暴露问题，不直接重写策略 | 新开“买卖指标优化”需求文档 |
| 修改配置影响原回测口径 | 历史结果不好对比 | 实施计划中明确是否改配置，必要时保留原配置备份 | 回滚配置修改 |

## 11. 专家建议

本轮最重要的不是把指标调到“看起来更赚钱”，而是先把决策过程透明化。

专家建议采用两步走：

1. 第一阶段：只做 `NVDAUSDT / 英伟达` 单股票解释页，把每次买入、卖出整理成类 Excel 明细表。
2. 第二阶段：根据明细表暴露出来的问题，再决定是否调整买卖指标，例如是否要弱化单一新闻信号、增加趋势过滤、增加冷却时间或改变卖出规则。

原因是如果现在直接改指标，用户仍然不知道到底是新闻错、技术指标错，还是展示不清楚。先做明细表，才能让后续策略优化有依据。
