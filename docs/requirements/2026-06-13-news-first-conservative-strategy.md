# NVDA 新闻优先 + 技术确认保守型低频策略需求文档

## 1. 基本信息

- 需求名称：NVDA 新闻优先 + 技术确认保守型低频策略
- 所属项目：Bitget AI Hackathon，美股 AI 交易赛道
- 项目路径：`/Users/ada/Documents/bitget ai`
- 文档状态：草案，待用户确认后进入实施计划
- 需求来源：用户口述、策略解释质量问题、降低交易频率与提高胜率倾向
- 创建日期：2026-06-13
- 最近更新：2026-06-13

## 2. 背景

当前 NVDA 单股票页面已经能用类 Excel 表格展示每笔回测买卖原因，但用户发现当前买卖更像“技术指标触发”，新闻面只是附加解释。这样会带来三个问题：

1. 交易频率偏高，容易出现很多噪音交易。
2. 每笔交易的消息面依据不够强，比赛展示时说服力不足。
3. 用户希望提高胜率倾向，而不是追求更多买卖次数。

从美股消息面投资专家视角看，下一版应改为：

> 新闻是门票，技术是确认，交易是结果。

也就是说，先有足够强的新闻 / 事件，再由技术面确认是否入场或离场。技术指标不能单独频繁触发买卖。

## 3. 目标

1. 将策略口径从“技术指标主导买卖”调整为“新闻优先 + 技术确认”。
2. 采用保守型交易风格：强新闻事件和技术确认同时成立才买入或卖出。
3. 降低交易频率，减少无新闻支撑的噪音交易。
4. 提高每笔交易的可解释性，让页面能说明“为什么这条新闻值得交易”。
5. 为每条可追溯新闻提供“查看原文”按钮，方便用户和评委核验新闻来源。
6. 继续保持只读回测 / 模拟展示，不涉及真实下单、账户读取或资金操作。

## 4. 非目标

1. 本轮不做真实交易、自动下单、账户读取、余额读取、持仓读取。
2. 本轮不追求高交易频率，不以交易次数多作为成功标准。
3. 本轮不做复杂机器学习新闻打分模型。
4. 本轮不新增自定义新闻爬虫，优先继续使用现有事件文件和 Bitget 官方技能口径。
5. 本轮不引入新前端框架、数据库或后台常驻任务。
6. 本轮不记录可直接实盘运行的完整私有策略参数。

## 5. 核心策略口径

### 5.1 总原则

1. 没有新闻 / 事件门票，不交易。
2. 新闻方向不清楚，不交易。
3. 新闻强但技术面不确认，先观察，不追。
4. 技术指标单独发出信号，但没有新闻支持，不买入。
5. 宁可少做交易，也要让每一笔交易有可解释理由。

### 5.2 新闻强度分层

| 新闻强度 | 定义 | 交易资格 |
| --- | --- | --- |
| 强利好 | 财报超预期、上调指引、AI 需求明显增强、重大订单、关键客户需求、分析师显著上调 | 可以进入买入候选 |
| 利好 | 行业需求改善、产品进展、普通分析师正面观点、市场情绪改善 | 只能观察或等待更强技术确认 |
| 中性 | 无明确方向、仅一般报道或重复旧信息 | 不交易 |
| 利空 | 需求放缓、估值压力、一般负面观点、行业竞争压力 | 观察或风控提示 |
| 强利空 | 指引下调、监管限制、出口禁令、重大客户风险、财报明显不及预期 | 可以进入卖出候选 |

### 5.3 买入条件

买入必须同时满足：

1. 新闻强度为“强利好”。
2. 新闻方向为看多。
3. 技术面已确认，例如短期趋势走强、价格站上短期均线或关键位置。
4. 不是明显追高状态，例如短时间大涨后技术面过热。
5. 距离上一次同方向买入已超过冷却时间。

如果新闻为“利好”但不是“强利好”，默认不买入，只显示“观察”。除非后续用户另行确认放宽为平衡型。

### 5.4 卖出条件

卖出满足以下任一情况：

1. 出现“强利空”新闻，并且技术面转弱。
2. 持仓后技术面明显破位，触发保守风控退出。
3. 出现强利好后买入，但后续价格没有跟随，达到预设观察失败条件。

普通小波动或中性新闻不应频繁卖出。

### 5.5 观望条件

以下情况应显示为“观望”，而不是买入或卖出：

1. 新闻强，但技术面未确认。
2. 技术面走强，但新闻面无明确支持。
3. 新闻为中性或来源不够明确。
4. 处于冷却时间内。
5. 新闻不错但不够强，尚未达到保守型买入门槛。

### 5.6 冷却时间

初始建议采用 12 小时冷却时间：

- 同方向买入后，12 小时内不重复买入。
- 同方向卖出后，12 小时内不重复卖出。
- 冷却时间用于减少重复信号和噪音交易。

## 6. 页面展示需求

### 6.1 决策表新增字段

现有 NVDA 决策明细表需要新增或强化以下字段：

- 新闻强度：强利好 / 利好 / 中性 / 利空 / 强利空
- 新闻方向：看多 / 看空 / 无方向
- 技术确认：已确认 / 未确认
- 冷却状态：可交易 / 冷却中
- 最终动作：买入 / 卖出 / 观望
- 查看原文：可点击按钮
- 决策原因：用中文解释新闻和技术面如何共同决定动作

### 6.2 “查看原文”按钮

每条有新闻来源的信号必须支持来源追溯。

按钮文案统一为：

> 查看原文

按钮规则：

1. 如果新闻记录有真实 URL，按钮点击后新开浏览器标签页打开原文。
2. 如果新闻没有 URL，但来自 Bitget 官方技能或结构化信号，按钮点击后在页面内展开信号详情。
3. 如果没有匹配新闻，则不显示可点击按钮，显示灰色文本：无新闻来源。
4. 按钮不能跳转当前页面，避免用户看完新闻后丢失回测表格位置。

### 6.3 页面解释口径

页面不能再只写“技术原因触发买入 / 卖出”。应改成类似：

- 买入：因为强利好新闻成立，并且技术面确认，所以回测触发买入。
- 观望：新闻不错，但技术面未确认，保守型策略不追。
- 观望：技术面走强，但没有足够新闻门票，保守型策略不买。
- 卖出：强利空新闻成立，并且技术面转弱，所以回测触发卖出。

## 7. 输入与输出

### 输入

| 输入项 | 来源 | 格式 | 是否必填 | 说明 |
| --- | --- | --- | --- | --- |
| 新闻事件记录 | `data/events/us_stock_events.json` 或 Bitget 官方技能产物 | JSON | 是 | 包含标题、来源、时间、URL、情绪、理由 |
| 回测交易记录 | `reports/latest/trades.csv` | CSV | 是 | 提供买卖时间、价格、数量 |
| 交易解释记录 | `reports/latest/trade-explanations.json` | JSON | 是 | 用于连接新闻、技术原因和交易动作 |
| K 线快照 | `reports/latest/candles.json` | JSON | 是 | 用于技术确认和趋势判断 |
| 策略配置 | 现有配置或后续新增保守型配置 | JSON | 是 | 记录冷却时间、新闻门槛、技术确认口径 |

### 输出

| 输出项 | 去向 | 格式 | 成功标准 |
| --- | --- | --- | --- |
| 保守型决策结果 | 页面 / 回测报告 | 表格 / JSON | 每行能说明新闻强度、技术确认和最终动作 |
| 查看原文按钮 | 页面 | 链接按钮 / 展开详情 | 有 URL 的新闻可以新开标签查看原文 |
| 观望记录 | 页面 | 表格行 | 新闻不错但技术未确认时显示观望，不强行交易 |
| 回测交易减少 | 回测报告 | 指标 | 交易频率低于当前技术触发版本 |
| 安全提示 | 页面 | 中文文本 | 明确只读回测，不下单、不查账户、不展示密钥 |

## 10. 风险与回退

| 风险 | 影响 | 预防方式 | 回退方式 |
| --- | --- | --- | --- |
| 交易太少 | 页面可能显得没有动作 | 明确本策略目标是保守低频，不追求次数 | 可后续切换为平衡型 |
| 新闻打分过粗 | 强利好 / 利好区分不准 | 先用关键词和来源口径做可解释规则 | 后续引入更细评分 |
| 有新闻但无 URL | 无法打开原文 | 页面内展示结构化信号详情 | 后续优化新闻源 |
| 技术确认过严 | 错过机会 | 先保守，保留观望记录 | 后续放宽为平衡型 |
| 误导为投资建议 | 合规风险 | 页面明确只读回测和模拟解释 | 保留安全提示 |

## 11. 专家建议

美股消息面专家建议本轮不要追求“更多交易”，而是追求“更少但更有理由的交易”。

推荐先采用保守型：

1. 强利好新闻是买入门票。
2. 技术确认是入场开关。
3. 强利空新闻或技术破位是退出理由。
4. 新闻不错但技术不确认时，记录为观望。
5. 每条新闻都尽量能点“查看原文”，让评委知道信号来源可核验。
